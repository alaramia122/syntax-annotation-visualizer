# ADR-004. Координаты и линии ролей

**Статус:** принято  
**Дата:** 2026-10-17

## Контекст

Контракт хранит смещения в кодовых точках Unicode. Индексы строк JavaScript — единицы UTF-16. У токена не больше одной роли, а пересечение диапазонов токенов уже запрещено валидатором. ТЗ просит линии под словами, а не заливку и не дуги зависимостей.

## Варианты

1. Сервер отдаёт исходные координаты. Клиент один раз строит таблицу «кодовая точка → индекс UTF-16» и режет ею текст.
2. Сервер заранее переводит координаты в UTF-16 и меняет контракт для браузера.
3. Рисовать дуги `head` или несколько линий на одном диапазоне.

## Решение

Принят вариант 1. Преобразование живёт в клиентском модуле координат. Сервер не отдаёт второй набор индексов.

На один токен приходится одна линия:

| Роль в разметке | Линия |
|---|---|
| `SUBJECT`, `ПОДЛЕЖАЩЕЕ` | сплошная |
| `PREDICATE`, `СКАЗУЕМОЕ` | двойная |
| `DEFINITION`, `ATTRIBUTE`, `ОПРЕДЕЛЕНИЕ` | волнистая |
| `OBJECT`, `ДОПОЛНЕНИЕ` | пунктирная |
| `ADVERBIAL`, `ADVERBIAL_MODIFIER`, `ОБСТОЯТЕЛЬСТВО` | штриховая |
| любое другое непустое значение | нейтральная сплошная, серая |
| роль отсутствует | линии нет |

Цвет линии только усиливает тип, но не заменяет его. Палитра: `#315d80`, `#6b3f2a`, `#3d6b4f`, `#6a4a78`, `#8a5a2b`, нейтральный `#5c6770`. Неизвестная роль не приписывается к одной из пяти групп. Легенда показывает пять ролей и пункт «другая роль».

Заливка слова цветом роли не используется. Выделение выбранного слова — отдельное состояние, не обозначение роли. Дуги зависимостей в первую версию не входят.

## Последствия

Накладывать несколько линий на один диапазон не нужно: валидный документ этого не содержит. Текущий `static/app.css` уже задаёт пять типов подчёркивания, но ещё не красит линии и не рисует нейтральную линию неизвестной роли. Это расхождение реализации этапа 5, а не открытый архитектурный вопрос.
