# ADR-001. Минимальный стек

**Статус:** принято  
**Дата:** 2026-10-17

## Контекст

Нужно выбрать стек до дальнейшего разделения кода. Контракт входных данных уже зафиксирован. ТЗ требует Python на сервере, HTML/CSS, JavaScript, загрузку JSON, проверку и визуализацию. Собственный синтаксический анализ, аккаунты и хранение документов между сеансами в первую версию не входят.

## Варианты

1. Оставить Flask, JSON Schema, ванильные HTML/CSS/JS и pytest.
2. Заменить сервер на FastAPI или Django.
3. Перенести интерфейс на React или другой SPA-фреймворк со сборкой.
4. Добавить библиотеку NLP, чтобы строить разметку в приложении.

## Решение

Принят вариант 1.

- Python не ниже 3.10.
- Flask — страницы и приём файла. Отдельного JSON API для документа нет: проверенный документ встраивается в HTML.
- `jsonschema` (Draft 2020-12) — структурная проверка.
- `src/annotation_validator.py` — семантическая проверка.
- HTML, CSS и JavaScript без сборщика и без фреймворка интерфейса.
- pytest — автоматические проверки.
- Зависимости только из `requirements.txt` / `pyproject.toml`. Новую зависимость можно добавить только с записью в журнале решений и причиной, которую нельзя закрыть уже имеющимся стеком.

## Последствия

Варианты 2 и 3 не дают обязательной возможности, которой нет у текущего стека, но добавляют сборку или каркас. Вариант 4 противоречит ТЗ. Поиск употреблений и карточка работают в браузере по уже проверенному документу. Исключение — словарная справка: её запрос идёт на серверный адаптер, см. ADR-003.
