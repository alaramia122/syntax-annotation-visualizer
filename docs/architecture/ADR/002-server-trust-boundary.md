# ADR-002. Сервер — граница доверия для документа

**Статус:** принято  
**Дата:** 2026-10-17

## Контекст

Один и тот же JSON можно было бы проверять и на сервере, и в браузере. Две реализации расходятся. Пользовательский текст нельзя трактовать как HTML.

## Варианты

1. Сервер проверяет документ целиком. Клиент рисует только документ, который сервер уже принял, и дополнительно не падает на неожиданном поле.
2. Клиент повторяет JSON Schema и семантические правила и сам решает, показывать ли документ.
3. Клиент показывает документ до проверки, а ошибки дорисовывает позже.

## Решение

Принят вариант 1.

- `POST /upload` принимает файл только после структурной и семантической проверки.
- При любой ошибке загрузки страница не показывает предыдущий и новый документ. Остаётся сообщение об ошибке.
- В HTML документ попадает через экранирование шаблона и JSON-встраивание. Клиент пишет текст только в текстовые узлы и `textContent`, не через `innerHTML`.
- Защитные проверки в JavaScript не заменяют серверные и не считаются второй спецификацией.

## Последствия

Невалидный файл не становится источником разметки. Расхождение правил исправляется в Python-валидаторе и тестах, а не отдельным клиентским списком кодов.
