# Текущая точка продолжения проекта

Обновлено: 2026-10-17

## Общий статус

**Этап 1:** закрыт. Формат входных данных определён, задокументирован и проверяется автоматически.  
**Этап 2:** закрыт как проектное решение. Стек, ответственность компонентов, интерфейсы и состояния интерфейса записаны в `docs/architecture/ARCHITECTURE.md`. Код ещё не разнесён по всем целевым модулям; это не хвост критерия этапа 2.  
**Следующий этап:** 3, подготовка среды. Репозиторий, зависимости, инструкция запуска и workflow CI уже есть; формально этап не закрыт, пока установка и запуск не подтверждены отдельной проверкой.  
**Веб-интерфейс:** начальный Flask-каркас есть. Он не считается принятой реализацией этапов 5–7: неизвестная роль без нейтральной линии, поиск не сгруппирован по ролям.  
**Справка:** порта в коде нет. До этапа 8 клиент должен показывать «источник не подключён».  
**Релиз:** отсутствует.  
**Локальный запуск тестов:** `python3 -m pytest -q` на Python 3.10.22 — 33 passed (0.11 s), 2026-10-17, после документов этапа 2. Код тестов эта правка не меняла. Журнал GitHub Actions для коммита на момент записи не проверялся.

## Подтверждённые источники

- Исходное техническое задание: «Разработка веб-приложения для визуализации синтаксической разметки русскоязычных текстов», версия 1.0.
- Исходный план разработки проекта «Визуализатор синтаксической разметки».
- Issue [#1](https://github.com/alaramia122/syntax-annotation-visualizer/issues/1) — приёмка этапа 1. На 2026-10-17 issue ещё не был закрыт формой GitHub, хотя критерий этапа в `main` уже выполнен коммитом `1c4917a`.

Ключевые требования: визуализировать заранее размеченный русский текст; не выполнять самостоятельный синтаксический анализ; сохранить исходный текст и координаты; поддержать карточку слова, поиск по словоформе/лемме и справочную функцию, которая не ломает основные сценарии при недоступности источника.

## Критерий этапа 2

План: определены архитектура и ответственность компонентов.

- Стек: Python 3.10+, Flask, jsonschema, ванильные HTML/CSS/JS, pytest. ADR-001.
- Граница доверия: сервер проверяет документ до показа. ADR-002.
- Справка изолирована, источник не выбран. ADR-003.
- Координаты переводит клиент; одна линия на токен. ADR-004.
- Состояния страницы, ошибок и карточки: `docs/architecture/ui-states.md`.
- Целевые модули и то, чего в коде ещё нет, перечислены в таблице `docs/architecture/ARCHITECTURE.md`. Отсутствие `src/dictionary.py` и `src/document_loader.py` не оставляет границу непринятой.

## Критерий этапа 1

План: формат входных данных определён, документирован и допускает автоматизированную проверку.

- Обязательные поля, типы, предложения, токены и связи описаны в `docs/specifications/input-format.md` и `schemas/annotation.schema.json`.
- Координаты `unicode_codepoints` описаны в `docs/specifications/coordinates.md`.
- Семантические коды перечислены в `docs/specifications/validation-rules.md` и реализованы в `src/annotation_validator.py`.
- Неоднозначности зафиксированы решениями D-005, D-006 и D-007.
- 11 валидных и 18 невалидных JSON-фикстур. Ожидаемый слой проверки задаёт `tests/test_fixtures.py`.

## Выполнено раньше и остаётся в силе

- Публичный репозиторий, README, `AGENTS.md`, ТЗ, план.
- `app.py`: демонстрационный документ, загрузка JSON, структурная и семантическая валидация, лимит 2 МиБ.
- Начальные HTML/CSS/JavaScript: текст текстовыми узлами, карточка токена, совпадения по словоформе и лемме, перевод координат в индексы UTF-16, пять типов подчёркивания.
- Workflow GitHub Actions для Python 3.10, 3.11 и 3.12.
