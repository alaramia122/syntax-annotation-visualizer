# Журнал проектных решений

Здесь фиксируются решения, влияющие на требования, формат данных, архитектуру и совместимость. Для существенных решений при необходимости создаются отдельные ADR в `docs/architecture/ADR/`.

## D-001. Приложение визуализирует готовую разметку

**Статус:** принято по ТЗ.  
**Решение:** приложение не выполняет самостоятельный синтаксический анализ и не определяет роли по исходному тексту.  
**Причина:** это явно ограничено техническим заданием.  
**Последствия:** входной JSON должен содержать текст и соответствующую разметку; валидатор проверяет данные, но не «исправляет» лингвистический анализ.

## D-002. Исходный текст — канонический источник

**Статус:** принято по ТЗ.  
**Решение:** отображаемый текст берётся из исходной строки. Токены ссылаются на её диапазоны; текст нельзя восстанавливать конкатенацией токенов.  
**Причина:** иначе возможна потеря пробелов, пунктуации и переносов строк.  
**Последствия:** координатная система и её Unicode-семантика должны быть однозначно описаны и покрыты тестами.

## D-003. Неизвестные лингвистические сведения не угадываются

**Статус:** принято по ТЗ.  
**Решение:** отсутствующие лемма, часть речи, грамматические признаки или роль не заменяются предположениями.  
**Причина:** приложение представляет имеющуюся разметку, а не генерирует анализ.  
**Последствия:** модель данных и интерфейс должны явно поддерживать неполные сведения.

## D-004. Справочная функция изолирована от основной логики

**Статус:** принято по ТЗ.  
**Решение:** источник словарной справки подключается через отдельный модуль; отказ источника не нарушает отображение, карточку и поиск.  
**Причина:** доступность и условия программного использования источника пока не подтверждены.  
**Последствия:** источник и способ интеграции выбираются после отдельного исследования.

## D-005. Поверхность токена не передаётся отдельным полем

**Статус:** принято при закрытии этапа 1.  
**Решение:** контракт v1.0 не содержит поля surface. Поверхность токена — всегда `document.text[start:end]`.  
**Причина:** отдельное поле расходилось бы с правилом «текст нельзя восстанавливать из токенов» и создавало бы второй источник символов.  
**Последствия:** пункт правил валидации про «явно переданную форму» к этому контракту не применяется.

## D-006. Связи `head` образуют лес без циклов

**Статус:** принято при закрытии этапа 1.  
**Решение:** самоссылка запрещена (`self_head`). Более длинный цикл запрещён (`head_cycle`). Голова должна быть в том же предложении. Несколько узлов с `head: null` и полное отсутствие корня допустимы. Ровно один корень на предложение не требуется. `relation: "root"` обязан иметь `head: null`; обратное неверно: `head: null` без `relation` не переписывается в `root`.  
**Причина:** циклы делают навигацию по связи неоднозначной. Требование единственного корня отвергало бы частичную разметку и не следует из ТЗ.  
**Последствия:** валидатор сообщает `head_cycle` и не «выбирает» корень за автора разметки.

## D-007. Код языка не ограничивается значением `ru`

**Статус:** принято при закрытии этапа 1.  
**Решение:** `document.language` — непустая строка. Схема не содержит перечисления языков.  
**Причина:** ТЗ задаёт назначение для русскоязычных текстов, но не список допустимых меток. Отвергать `ru-RU` или иной ярлык было бы скрытым предположением.  
**Последствия:** приложение не выводит язык из букв текста и не подменяет метку.
