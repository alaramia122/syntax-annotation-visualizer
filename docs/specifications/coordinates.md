# Координатная система

**Статус:** зафиксировано по ТЗ.

Для первой версии используются целочисленные смещения в Unicode-кодовых точках Python (`unicode_codepoints`).

## Правила

- Диапазон полуоткрытый: `[start, end)`; `start` входит, `end` не входит.
- Фрагмент извлекается как `text[start:end]`.
- Все координаты относятся к одной и той же неизменяемой исходной строке.
- Запрещено смешивать UTF-8 byte offsets, Unicode code points и UTF-16 code units.
- Координаты должны быть целыми числами; логические значения Python не принимаются как координаты, несмотря на наследование `bool` от `int`.
- Для токена требуется `0 <= start < end <= len(text)`; для предложения допускается пустой диапазон `0 <= start <= end <= len(text)`.
- Токен должен целиком находиться внутри диапазона указанного предложения.
- Диапазоны токенов не должны пересекаться; порядок токенов в массиве должен соответствовать порядку в тексте.
- Токен не может состоять только из пробельных символов. Словесный токен не может включать пробельные символы внутри диапазона.
- Промежутки между токенами разрешены: исходные пробелы, табуляции и переносы строк не удаляются и не обязаны представляться токенами.

## Совместимость Python и JavaScript

Python индексирует строки кодовыми точками Unicode. Индексы JavaScript-строк выражаются в UTF-16 code units. Поэтому нельзя напрямую применять Python-координаты к строковым индексам JavaScript для символов вне базовой многоязычной плоскости. Клиент строит таблицу перевода и не меняет контракт. Сервер второй набор индексов не отдаёт. Это граница из [ADR-004](../architecture/ADR/004-rendering-and-coordinates.md).

## Проверки

Нужны тесты для кириллицы, пунктуации, табуляции, переносов строк, комбинируемых знаков и символов вне BMP, например emoji. Проверка соответствия токена исходному тексту выполняется с использованием Python-среза `text[start:end]`.
