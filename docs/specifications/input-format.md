# Формат входных данных

**Статус:** проектируется; не считать этот документ окончательным контрактом.

## Общие требования из ТЗ

- Формат обмена — JSON.
- Документ содержит исходный текст и готовую синтаксическую разметку.
- Исходный текст является первичным источником символов, пробелов, пунктуации и переносов строк.
- Разметка ссылается на участки исходного текста координатами.
- Запрещено восстанавливать исходный текст путём объединения токенов.
- Необходимо проверять структуру, типы, координаты, порядок токенов и ссылки между элементами.
- Отсутствующие лингвистические сведения не должны подменяться догадками.

## Что необходимо определить до утверждения схемы

- Версию формата.
- Обязательные и необязательные поля документа.
- Представление предложений и токенов.
- Идентификаторы и их область уникальности.
- Поля леммы, части речи, грамматических признаков и синтаксической роли.
- Представление отношений/голов, если оно требуется выбранной моделью.
- Допустимость неполной разметки.
- Правила обработки неизвестных ролей.
- Ограничения размера и количество элементов.
- Политику неизвестных дополнительных полей.

## Требование к реализации

Структурная схема и семантический валидатор должны быть раздельными. JSON Schema проверяет структуру и типы; прикладная проверка — согласованность координат, уникальность идентификаторов, ссылочную целостность и другие межполевые ограничения.
